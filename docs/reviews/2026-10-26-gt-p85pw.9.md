## Findings

1. **major — `internal/beads/kv_test.go:147-154`.** `TestKVGetRefusesAFlagLikeKey`
   asserts only that *some* error comes back, and gets it by running a real
   `bd`: with the guard deleted (M1) the fallthrough `bd kv get --force --json`
   exits 27 and the test still passes, so the commit's "a flag-like key is
   refused" is pinned by nothing. The package's recorder seam
   (`newRecorder`/`newRecordedBeads`, `runner_helpers_test.go:46`) is what
   `TestKVMethodsSendTheirArgv` already uses, and would let the test assert the
   guard's error *and* that no `kv get` argv was issued. Found bead:
   **gt-ttwzj**.
2. **major — `internal/beads/beads.go:2026-2028`.** The empty-envelope branch
   cannot run: `decodeMachineEnvelope` returns `ok == false` unless the object
   has a `data` key (`machine.go:54-56`), and a present key unmarshals to at
   least `null`, so `len(env.Data) == 0` never holds once `ok` is true. The
   coverage profile counts the branch body at `:2027-2028` as executed zero
   times. `TestParseKVListJSONEnvelopeWithNoDataIsEmpty` feeds
   `"data":null`, which reached an empty map through `json.Unmarshal("null",
   ...)` before the change too — M3 reverts the branch and the test stays
   green. The shape the comment names (an envelope with no data key) still
   falls through `kvPayload`'s `return out` at `:2024` and is parsed as the
   store: P1 surfaces `error=not found` as an entry. The commit's headline
   criterion has no effective test. Found bead: **gt-ij4fl**.
3. **minor — `internal/beads/trackerclient/admin.go:35-47`.** `KVList` and
   `KVGet` return `errTrackerKV`, and no test in the package mentions either
   method or the error (zero grep hits across its `*_test.go`), though dipper's
   comment on gt-p85pw.9 asked for "a unit test that the error is returned and
   no request is sent". The comment claims the error stops a tracker rig
   reading as having no memories "without anyone being told", but the only
   non-test consumer cannot reach it: `internal/cmd/prime.go:883` reads the
   store through `beads.New(workDir).KVList()` — the bd wrapper, never
   `backend.Open`'s tracker client, which has no production caller — and
   `internal/cmd/prime.go:870-873` silently discards any error it does get.
   Found bead: **gt-2w29i**.
