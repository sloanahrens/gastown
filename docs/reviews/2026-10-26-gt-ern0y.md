## Findings

1. **major — `internal/land/land.go:2027-2029` with `:2002`.** The clamp
   changes a value that is also an identity key. `gt land requeue` records the
   capped attempt (`internal/cmd/land.go:199` passes `note.Attempt`, now 3).
   `rejectionAlreadyRecorded` reads "the newest REQUEUED comment names this
   block's attempt" as *the block was finished* (`land.go:2002`). After a
   capped rejection is re-queued and the next resubmission is rejected, the new
   block is also written as attempt 3, so an interrupted pass (the reopen
   failed) has `last.Attempt == RequeuedAttempt` and the retry appends a second
   block instead of finishing the first — the duplicate the gt-zqqcr/gt-en9gs
   guard exists to prevent, burning a refusal the author never saw. Probe 1
   reproduces it. Found bead: **gt-kwe1l**.
2. **major — `internal/land/land.go:2027-2029` with `:946`.** `logReview`
   still writes `Attempt: CountRejections(issue.Notes) + 1`, and both its doc
   comment and `ReviewRecord`'s state that this is "the one a rejection would be
   recorded as, so a bead's lines count up with its MERGE REJECTION blocks".
   Above the ceiling that is no longer true: probe 2 logs attempt 4 for a block
   that says 3 on the same round. Static consequence, not run: the rework
   reader matches a record to a block by attempt number
   (`internal/jev/rework/rework.go:304-314`), so a record for attempt 4 finds
   no block, the refusal is `errUnreadable`, and the pass skips it. Found bead:
   **gt-k10bq**.
