## Checks beyond the mutations

- **"The alarm stub no longer spins on EOF"** (the commit's headline): true, and
  M1 measures it — 4.05 s CPU → 0.012 s over the same window. The reader returns
  on end of file or an error and closes the alarm channel only for a line. No
  test holds it (Finding 1).
- **"The close test checks the descriptors are closed (EBADF), on high
  descriptor numbers nothing else is handed, and fails instead of skipping"**:
  the test does all three (`supervisor_test.go:529`, `:543`, and `highFd`'s
  `t.Fatalf` at `:562`), and M2/M3 show the first two are load-bearing. `highFd`
  fails rather than skipping the assertion when the duplicated fd is above 255 —
  fail-closed.
- **"waitGone's loop variable no longer shadows the waited type"**: a rename at
  `supervisor.go:205` and `:208`; the loop's probe-then-check-then-sleep shape
  and its limits are unchanged, so there is no behaviour to pin.
- **The two changes the message attributes to the first commit**: the file does
  carry them at this commit — there is no Case 45, Case 41 is "the image
  supervisor cannot be built", and `TestIntegrationLockOfAnotherProcessStaysAfterTheStop`
  is at `process_integration_test.go:308`. The message says so plainly instead
  of leaving the omission in `132c3759f`.
- **"The build's stdin is now /dev/null"**: `startBuild` leaves `cmd.Stdin`
  nil (→ `/dev/null`), and `install-gt.sh` already ran the call as
  `( image_build … ) </dev/null`, so no build could read anything different.
- **Hermetic:** the unit test opens real pipes and closes every fd it opened in
  `t.Cleanup`; no subprocess, no sleep, no environment or host file read.
- **Scope:** four files, all named by the diff's own subject; nothing outside
  the supervisor and its test.
