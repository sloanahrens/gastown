# Second look: gt-xzo8a, the install lock wait raised to cover the image build

Reviewed commit: `b25963ac729a` — "install: a queued install waits for the whole image
build; the default lock wait is the alarm bound plus a minute (gt-xzo8a, hq-ltx66)". One
file, `scripts/install-gt.sh` (+6/−1). It is an ancestor of `origin/main`; nine later
commits touch that file, and the hunk is unchanged on main at `scripts/install-gt.sh:185-187`,
so this reviews what main runs (cited below at both the commit's and main's line numbers).

The change: `LOCK_WAIT` no longer defaults to 300. It defaults to `lock_floor + 60`, where
the floor is `IMAGE_ALARM` when that is a positive integer and 1200 otherwise — the same
1200 the image step falls back to for a bad alarm.

Why it exists: om rejected gt-xzo8a for holding the install lock across a synchronous image
build, Robin put the choice to Sloan, and Sloan answered to keep the lock and raise the wait
(hq-ltx66). The overseer then recorded a CONCERN on the landed commit: the default rises from
300s to 1260s with shell logic no test covers. This review is that second look.

| M4 | `^[1-9][0-9]*$` → `^[0-9]+$` (accept a zero alarm: `INSTALL_GT_IMAGE_ALARM=0` then gives a 60s queued wait for a build bounded at 1200) | **GREEN** |
| M5 | `lock_floor=$IMAGE_ALARM` unconditional (drop the alarm validation) | **GREEN** |

The reason all five survive is one line in the harness: `run_install`
(`scripts/install-gt_test.sh:164`) and `run_install_at` (`:182`) export
`INSTALL_GT_LOCK_WAIT="${LOCK_WAIT:-5}"` on every run, so `${INSTALL_GT_LOCK_WAIT:-…}` never
expands its default word and the new logic never executes. M5 proves it: with the guard
gone, an alarm of `soon` reaches `$((lock_floor + 60))` and bash 5.2 aborts the script under
`set -u` (`soon: unbound variable`), yet Case 46 still passes because the wait is never
computed.

## Checks beyond the mutations

- **Scope:** one file, six added lines, one removed, no dependency, no unrelated file. A
  correct split from gt-xzo8a's acceptance boxes — the boxes cover build-before-swap only,
  and none of them covers this default.
- **Test shape:** the commit adds no test, so the sleep/poll, subprocess and fixture rules
  have nothing to grade. It also adds no script.
- **The arithmetic is bounded by nothing.** `^[1-9][0-9]*$` accepts any positive integer, and
  `lock_floor + 60` wraps at int64: the probe shows an alarm of 2^63−1 yields a negative
  wait. On main `cmd/install-lock/main.go:35` refuses `--wait < 0`, so the install fails as
  "unexpected" instead of waiting. The input is absurd (2^63−1 seconds); recorded as a note,
  not a defect.
- **The default reaches only manual and post-land runs.** rebuild-gt, the automated caller,
  pins `INSTALL_GT_LOCK_WAIT=60` (`internal/daemon/rebuild_gt.go:705`) on purpose, to keep the
  rebuild job idle and its upgrade restart prompt. So the raised default buys waiting time for
  `make install` and post-land, not for the daemon.
- **The Go port would not carry the fix.** `internal/installer/lock.go:10-20` keeps
  `DefaultLockWait = 300` and documents a different design — "the image build runs before the
  lock is taken and holds only its own polecat-image lock". Nothing calls `cmd/gt-installer`
  yet, so this is a divergence to decide when the port lands, not a defect here.

## Findings

1. **major — `scripts/install-gt.sh:169-171` (`:185-187` on main) is reached by no test.**
   Five mutations of it (M1–M5), including a full revert to the old default, leave
   `bash scripts/install-gt_test.sh` green because both install runners export
   `INSTALL_GT_LOCK_WAIT` (`scripts/install-gt_test.sh:164, :182, :540`). A later edit can
   restore 300, drop the minute, or drop the alarm validation with nothing to stop it; the
   commit's own subject is the claim, and nothing checks it. Found bead: **gt-d8aul**.
2. **minor — `scripts/install-gt.sh:171` (`:187` on main) bounds the image alarm, not the
   lock hold.** The lock is taken before the container-gate slot wait (`:609`, default
   `SLOT_TIMEOUT=600` at `:81`) and before `make build` (`:630`), and both are part of the
   holder's lock hold; rebuild-gt has measured gate holds of 2m–20m20s
   (`internal/daemon/rebuild_gt.go:60-65`). A queued install waits alarm+60 from its own
   start, so it can still be refused busy while the holder is inside a slot wait, before the
   image build has begun. The subject's "waits for the whole image build" holds for the
   no-slot path only. Found bead: **gt-ujlhx**.

## Verdict

POLECAT REVIEW b25963ac729a FAIL: scripts/install-gt.sh:171 (main :187) computes the new default lock wait with no test that reaches it — every one of five mutations, including a revert to the old 300, leaves the suite green because scripts/install-gt_test.sh:164 and :182 export INSTALL_GT_LOCK_WAIT on every run (Found gt-d8aul); and the wait bounds the image alarm only, while the slot wait and the build that precede it are part of the same lock hold, so a queued install can still be refused busy (Found gt-ujlhx)
