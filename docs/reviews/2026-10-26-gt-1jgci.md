## Checks beyond the mutations

- **Hermetic:** the new tests use `t.TempDir()`, the injected `fakeClock` and the
  `recorder` exec seam. No sleep, no poll, no subprocess, no package-variable
  swap, no host state; both new tests run with `Wait` at zero, so the lock is
  taken on the first `flock` and no wall time passes.
- **The removed test was a source-text test.** `TestInstallScriptNeverExitsTheLockBusyStatus`
  read `scripts/install-gt.sh` and grepped it for a comment string and `exit\s+75`.
  Removing it with the `regexp` import follows the repo's test norms.
- **What the removal gives up:** nothing in the tree now pins "the install never
  exits 75". The gt-1jgci notes say that claim was "pinned by a test"; after
  this commit it is prose in two comments. That is the trade the commit names in
  its subject, and the claim is not observable without a run that reaches the
  path, so I read the deletion as correct rather than as a weakened guard.
- **The new refusal path ends where it should.** A marker that cannot be removed
  returns 1 before the exec; the caller then still sees the marker, runs `rm -f`
  and its EXIT trap prints `failed ... unexpected` with exit 1, so
  install-gt.sh's contract holds. The lock is not leaked: `defer f.Close()` is
  registered before the guard, so the return releases the flock.
- **The put-back path is reported, not fixed.** When the marker cannot be
  written back, the caller sees no marker and concludes the install ran: it sets
  `RESULT_EMITTED=1` and exits 1 with no RESULT line, which `rebuild_gt.go:810`
  then never sees. The commit makes that case loud on stderr and says so in the
  message; the missing RESULT line is the cost of the marker design, and I read
  it as the accepted behaviour of this bead rather than as a defect.
- **Scope:** the diff is three files, all of them the lock helper and the script
  that calls it; no dependency, no unrelated file.
