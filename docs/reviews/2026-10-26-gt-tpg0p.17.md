## Probe of the call-site survivor

M15 survived the suite, so I checked what it does with a scratch test (not
committed) that calls `runWith` with a newline-bearing package, through the fake
host:

- Pristine reviewed commit: `rc=2`, `sendKeysRan=false`, `resultPolls=0`, stderr
  `test-timing: the pane cannot type a word holding a newline: "a\nb"`.
- M15 mutant: `rc=2`, `sendKeysRan=true`, `resultPolls=899`, stderr
  `test-timing: no result after 30 min; log: …`.

The newline never reaches the pane in either case, because the helper returns
`""` on refusal. The loss is the fail-fast refusal: with the caller's check
gone, the run types an empty line and waits out the whole result bound, about
30 minutes of real time in production (899 × 2 s), and no test notices.

## Findings

Two defects, both introduced or loosened by this commit. Each has a Found bead.

1. **The refusal at the `runTiming` call site is untested** (`main.go:178-182`).
   The commit tests `paneCommandLine` directly, not through the caller. Deleting
   the caller's `err` check (M15) leaves every test green, and the probe above
   shows the refused word then waits 30 minutes instead of failing at once.
   This is the house rules' "test the call site, not the helper" and "test the
   branch that refuses". Found bead **gt-44mzn**.

2. **The 30-minute wait bound is no longer pinned** (`main.go:74` and `:193`;
   `main_test.go` `TestRunTiming_Verdicts`, around lines 404 and 461-466). The
   commit replaced the exact `wantWaits: resultChecks - 1` assertion with
   `waits != 0` for a pane that never reports. Cutting `resultChecks` from 900 to
   2 (M17) keeps every test green. The run then gives up after about 4 s while
   the message at `main.go:193` still says "no result after 30 min", because
   that text is hard-coded. The commit message says the tests assert "what each
   call must accomplish … instead of … poll counts", but the bound itself is a
   behaviour the caller sees, and it is no longer tested. Found bead **gt-cpdm3**.

## Checks that held

- **Newline refusal:** M1 and M10 go red. The refusal runs before `shellQuote`,
  and `shellQuote` already handles embedded single quotes.
- **Mean, not median:** M2 and M4 go red. `measure` reads `Samples`, which
  `exectax.Probe` fills.
- **Whole-ms truncation:** M5 goes red. `TestMeasure_TruncatesMilliseconds` pins
  2.5 ms to 2.
- **Empty probe is a failure:** M3b goes red on an assertion, so the guard's own
  test checks the refusal (M3's panic alone would not show that).
- **Ordering:** the launchd job is removed before the pane is typed into (M6),
  and cleanup removes it on the way out (M16). M11b checks the ready poll.
- **Tier command:** the parallelism, the `--` separator and the default package
  list are pinned (M7, M8, M9).
- **Real host and integration:** `TestRealHost` (M18) and the integration
  runner's exit status (M19) both go red.
- **Test hygiene:** a grep of `main_test.go` finds no `time.Sleep`, no real clock
  wait and no `exec.Command`. The only subprocess is in
  `main_integration_test.go`, behind the `integration` build tag and named
  `TestIntegrationRunCommand`. The fake host's fields are struct fields, not
  package-variable swaps. The diff adds no `.sh`, `.pl` or `.rb` file.
- **Commit claims:** mean, whole-ms truncation, the empty-probe refusal and the
  real-host and integration tests are all tested. The newline refusal is tested
  through the helper only (finding 1).
