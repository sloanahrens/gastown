## Findings

1. **major — `internal/land/omstats.go:432`.** `omStatsLogRejectRe` matches only
   `rejected (review): om requested changes`, so the daemon-log fallback counts
   one of the two review-rejection reasons the worker writes. A bounced
   approval — om approves and `findingsRejection` refuses on the findings
   (`internal/land/land.go:857-869`) — is logged as `rejected (review): a
   <severity> finding blocks the landing at any score` or `… more than N minor
   findings …` (`land.go:2060`), and the record half counts it
   (`ReviewRecord.Rejected`, `reviewlog.go:38`, `IsRejection`). On the log half
   it is dropped entirely: the day loses both the rejection and any approval, so
   the rate falls and the two halves disagree on the same verdict. P1 measures
   it: one bounced approval plus one `om requested changes` rejection reports
   `Rejections: 1`, want 2. Only days before the review-records file begins are
   affected, which is exactly the historical backfill. Found bead: **gt-9wxef**.
2. **minor, test coverage — `internal/cmd/land_om_stats.go:131-134` and
   `:183-185`.** The town-resolution failure and a non-`fs.ErrNotExist` open
   failure are both error branches of new code with no test: C3 and C4 make each
   swallow its error and every test stays green. A future edit that turns a
   failed source read into an empty report would ship unobserved. Found bead:
   **gt-ud1nc**.
