## Findings

1. **minor, test coverage — `plugins/polecat-image/run.sh:357`, `:372`, `:310`.**
   The commit routes three more branches through the switch — the build path's
   held lock (`:357`), the sling that starts between build rounds (`:372`), and
   the tarball directory that cannot be made (`:310`) — and no case drives any of
   them: M4, M5 and M10 leave both suites green. Each is a path on which the
   pre-swap install would again swap a binary whose image is not in place if the
   line returned to `log`/`:`; `plugin.md:91-98` names the lock and the sling as
   covered. Found bead: **gt-i893i**. (Still open on main: the same nine closed
   cases, no new one.)
2. **minor — `plugins/polecat-image/plugin.md:154`.** The exit-status paragraph
   still says "A deferral is not a failure: it exits 0 and prints why", while
   bullet 2 (`:49`) and the new "Failing closed where it matters" bullet
   (`:91-98`) make every deferral fail under `POLECAT_IMAGE_FAIL_CLOSED=1`. The
   two statements are three lines apart in intent, not in text. Found bead:
   **gt-a2f61**. (Still present on main at `:155`.)

## Accepted

- **The deferred-failure deviation is right.** `gt-efupr`'s constraint says
  "Deferrals (docker down, a sling running, the lock held) stay exit 0"; the
  rework makes them fail under the switch instead. The bead notes flag this
  against the om finding that a deferral still let the install swap, and
  `plugin.md` documents it. Without it the switch does not deliver the criterion:
  a deferral is exactly the case where the image is not built.
- **Install contention.** The pre-swap build now fails the install when the
  plugin lock is held by another run (a trim or a daemon build). That is the
  documented contract and the image that other run makes is at the old commit,
  so the install's refusal is correct; it will show as a `build-failed`
  escalation, not a silent revert.
