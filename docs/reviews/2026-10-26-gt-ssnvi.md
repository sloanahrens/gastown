## Checks beyond the mutations

- **Hermetic.** No subprocess, no `os/exec`, no sleep and no polling on real
  time: every wait is a context deadline (5 s in `waitForLine`, 10 s in
  `waitForSignal`), which is the bound the first submission's testpolicy
  failure asked for. No environment or host-file read, no package-variable
  swap, no new `.sh`/`.pl`/`.rb` file.
- **The dropped signal cannot lose a line.** `Write` appends before it signals,
  and `waitForLine` scans the recorded lines before every wait, so a full buffer
  costs at most a coalesced wakeup. M2 is the only untested corner of that
  argument, and it names `waitForLine`, which `6fb30359` added rather than this
  commit; its failure mode is a spurious 5 s timeout (false red), not a pass. I
  recorded it here and filed no bead.
- **The guards it adds are load-bearing.** M1 (the commit's own line) and M3
  (the test's line assertion) both go red with the change reverted; M4 shows the
  wakeup is still required by `TestRunStartsTheCensusLogOnMinuteTicks`, so
  dropping it altogether is caught too.
- **Its premise holds elsewhere.** No test under `internal/daemon` reads
  `daemon.go` to count census strings; the only `daemon.go` reference in a test
  file is a git-status fixture at `rebuild_gt_test.go:136`.
- **Scope and hygiene.** One file, the test; `gofmt` clean; the commit message
  names the bead and carries no attribution trailers.
