# W2: bd verbs for every bd-table write, and gt shutdown refuses stray arguments

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans with superpowers:test-driven-development. Every task starts with a failing test.

**Goal:** gastown writes to bd tables only through bd verbs (so bd maintains `is_blocked`, the events journal and close metadata), keeps raw SQL for read-only candidate selection, deletes its wisp-table DDL, and `gt shutdown` (plus its lifecycle siblings) refuses positional arguments it would ignore.

**Architecture:** The reaper keeps its SELECTs (the protections live there) and hands the chosen ids to a `reaper.Writer`, which `*beads.Beads` satisfies with `bd close` and `bd delete --force` in machine mode (`BD_MACHINE=1`). The writer is pinned (`beads.NewRigLocal`) to the beads dir whose `metadata.json` names the database being reaped. Doctor fixers call per-id bd verbs. Data paths bd already covers (orphan dependency rows, the label-set anchor, the wisps migration and its DDL) are deleted.

**Tech Stack:** Go, bd CLI (fork D1 machine surface, beads da4983e), `internal/beads` runner seam (`NewWithBeadsDirAndRunner`), the reaper's fake `database/sql` driver.

**Spec:** gt-fcxe9.12, gt-fcxe9.14; ADR `docs/adr/0001-cli-only-beads-access.md` (D1); deep review B5-06, B5-16 (`~/.claude/docs/research/deep-review/beads-cross-cutting-contract.md`), G1-19 (`gastown-control-plane.md`); beads `engdocs/design/d1-machine-surface.md` at da4983e.

## Global Constraints

- No DML or DDL from gastown against bd tables (issues, wisps, labels, wisp_labels, comments, wisp_comments, events, wisp_events, dependencies, wisp_dependencies, config). No `DOLT_COMMIT` after a bd write: bd commits its own writes.
- Machine-mode exit codes: not_found 20, refused 21, partial 22, truncated 23. `bd close A B` reports a partial batch with `error.ids`; `beads.PartialCloseError` / `beads.ClosedIDs` already decode it.
- New `*beads.Beads` methods go in their own file and their own commit (overlap with crew/sloan/w2-client, which owns `internal/beads` library moves). They are not added to `beads.Client`, so `beadsfake` does not change.
- No test reaches the bd on PATH or a Dolt server.
- The command-tree lint (`internal/cmd/command_tree_lint_test.go`) stays green.
- No AI attribution in commits.
