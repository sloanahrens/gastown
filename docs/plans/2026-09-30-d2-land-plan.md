# D2: gt done submits only, and Land() lands on the merged tree

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans and
> superpowers:test-driven-development. Every task starts with a failing test.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `gt done` stops landing anything: it rebases, squashes, runs the local
gate, pushes the branch and marks the work bead ready to land. A new
`internal/land` package owns `Land()`, which merges the branch onto a
throwaway worktree of origin/target, gates the merged tree with om review
running beside it, pushes with a lease, reads the tip back and records the
landing on the work bead and in a per-rig landings file.

**Architecture:** `internal/land` is a leaf over `internal/git`,
`internal/beads` (the `Client` surface), `internal/checkpoint` and
`internal/dispatch`. It never imports `internal/refinery`; the refinery helpers
Land needs move into it and the refinery keeps thin wrappers until gt-v4ssj.6
deletes the refinery. `gt done` uses the same `land.Gate` seam as its local
pre-submit gate. The daemon landing worker (gt-v4ssj.2) is a later caller.

**Tech Stack:** Go, git CLI, bd CLI through `beads.Client`, om CLI.

**Spec:** ADR `docs/adr/0004-daemon-lands-work.md`; beads gt-v4ssj, gt-v4ssj.3,
gt-v4ssj.9; G2 review `~/.claude/docs/research/deep-review/gastown-landing-path.md`
("Phase 3 review" keep list, "Dark-factory fitness"); `d2-landing-evidence.md`;
the operator's hand procedure `land.sh` (merge --no-ff into a throwaway worktree
of origin/main, gate the merged tree by exit code, re-check main, push, read back).

## Global Constraints

- Local gate seam (until D9 defines `make gate`): `make lint`, `go build ./...`,
  `make test` with `GT_TEST_DOCKER=0` (the unit tier, no container slot). A rig
  without `go.mod` uses its merge_queue `lint_command`, `build_command`,
  `test_command`; a rig with none of them fails closed (G2-11).
- Land() gate: `make lint`, `go build ./...`, `make test` on the merged tree
  (container tier; the caller puts the test step under the container-gate slot
  through `land.WithSlot`, which takes the hold in process — gt-638go.12). om:
  `om review -C <wt> --base <base sha> --head <merge sha> --out <file>`,
  exit 0 approve, 1 request_changes, anything else is an infrastructure error.
- The ready marker is the label `gt:ready-to-land` on the WORK bead plus one
  `READY TO LAND` notes block (Branch, Head, Target, Worker). No MR wisp.
- Landing record: one `LANDING RECORD` notes block on the work bead written
  with `bd update <id> --append-notes` (`beads.Client.AppendNotes`), then
  `bd close <id> --force --reason` carrying `landed_commit:` and `patch_id:`.
  be-u20 replaces the notes block with a typed verb.
- Landings file: `<town>/.runtime/landings/<rig>.jsonl`, directory 0700, file
  0600, O_APPEND, one JSON object per landing, written after read-back and
  before the bead writes.
- Rejection: a `MERGE REJECTION (attempt N): <kind> - <reason>` block in the
  existing format plus `Head:`, `Conflicting:` and an indented gate tail; the
  bead goes to status open, assignee cleared, labels `-gt:ready-to-land
  +rework` (`no_merge` gets `gt:needs-human` instead of `rework`).
- gt done exit codes, all returned before the witness is told anything:
  10 push failed, 11 push unverified, 12 ready-to-land record failed,
  13 no-code close failed, 14 rebase conflict, 15 local gate failed,
  16 local gate could not run.
- Do not touch `doMerge`, batch, MR wisps, `gt mq`, the merge slot or
  `refs/notes/om` (gt-v4ssj.6). No flake reruns (gt-v4ssj.5), no red-main
  owner (gt-v4ssj.4).
- Temp files go under a 0700 directory the caller owns, never a fixed /tmp name.

## Landings file contract

This is a stable contract; readers (gt-tail and others) may depend on it.

- **Path:** `<town>/.runtime/landings/<rig>.jsonl`, where `<town>` is the
  town root and `<rig>` is the rig name (for example
  `~/gt/.runtime/landings/gastown.jsonl`). Built by
  `land.RigLandingsFile(townRoot, rig)`.
- **Permissions:** the directory is 0700 and the file 0600, both owned by the
  landing worker's user. A group- or world-writable directory, a directory
  owned by another uid, or a symlinked file is refused.
- **Format:** JSON Lines, UTF-8. One record per line, terminated by `\n`, and
  one line per landing.
- **Append-only:** each write is a single `write(2)` with O_APPEND, then fsync.
  Lines are never rewritten or removed. A reader must tolerate a missing file
  (no landings yet) and must ignore a trailing partial line.
- **When written:** after the push and the read-back of the target tip, and
  before the bead is updated. A line means the commit landed.
- **Record** (every field is always present):

| Field | Type | Meaning |
|---|---|---|
| `bead` | string | Work bead id, e.g. `gt-abc` |
| `rig` | string | Rig name |
| `branch` | string | Source branch that was landed |
| `head` | string | 40-hex commit gt done declared (READY TO LAND `Head:`) |
| `target` | string | Target branch, e.g. `main` |
| `base` | string | 40-hex target tip the merge was built on (the lease value) |
| `landed_commit` | string | 40-hex commit now at the target tip |
| `patch_id` | string | `git patch-id --stable` of `base..landed_commit` |
| `gate_result` | string | One-line gate summary, e.g. `pass (gate exit 0 7m12s)` |
| `om_verdict` | string | `approve` (only approved work lands) |
| `om_score` | number | om score, 0.0-1.0 |
| `route` | string | Who landed it: `daemon` for the landing worker |
| `landed_at` | string | RFC 3339 timestamp in UTC with a `Z` suffix, nanosecond precision allowed (Go `time.Time` JSON) |

- **Duplicates:** the same (`bead`, `head`) can appear more than once only if
  the target was rewound and the work landed again; the last line wins.
- **Change policy:** fields may be added, and are never renamed, retyped or
  removed.

## Decisions recorded

- Ready marker is a label, not a status: a new bd status needs custom-status
  registration in every rig DB, and the label needs nothing. The bead keeps
  its hooked/in_progress status until Land() closes or rejects it; the landing
  worker (gt-v4ssj.2) and orphan sweeps must treat the label as "owned by the
  landing worker".
- The no-code completion (zero commits ahead on no_merge, review_only or
  report-only work) stays in gt done: it pushes and lands nothing, and D2
  offers no other closer for work with no branch.
- no_merge work with commits is submitted like any other and Land() rejects it
  as policy with `gt:needs-human`, since only a human decides it.
- A failed gt done no longer reports done: the polecat keeps its session,
  the done-intent label is cleared, and the error names the next step.
